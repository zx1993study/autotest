# PunkRecord 功能流程整理结果

2026-10-21，项目 `17796`。本轮仅整理测试平台配置，没有执行业务接口、发放或扣除贝利、创建业务订单。

## 平台变化

- 原 138 个流程、141 个场景，归并为 9 个业务流程、70 个场景。
- 68 个单接口参数、授权、文档等校验条目不再作为独立流程。空文本、纯空格、长文本保留于原 API 正式用例，不再额外建立功能场景。
- 旧流程和场景软删除；相关 537 条原 API 用例、接口定义和 274 个历史运行批次保持原样，历史结果不改写。其他原 API 用例没有删除或修改。
- 增加 60 个跨场景共享 API/认证节点模板，均停用，避免成为单接口批量执行目标；场景保存实际请求和断言，不逐个测试点重复建立流程。
- 新流程、场景及共享节点全部停用，列表显示未执行，不复制旧的 latest_status/latest_run_id。

## 链路修正

- 商城下单引用已登记旧商品的分支，增加本场景新商品准备和响应 ID 传递，避免直接修改旧商品。余额预期仍需在隔离执行前按新基线重设。
- 早会在修改参会人之前增加新会议录入节点，响应 ID 传给后续参会人接口，不重放旧会议 ID。该入口是无音频录入，不代表 Word/PDF/音频上传已完成。
- 获取贝利按现有源码的“创建任务→提交完成→主管验收→L0奖励审核→到账”组织。用户所说开始任务前的审核入口尚待确认，不虚构接口。
- 原节点顺序、认证身份、完整断言、提取规则及参数绑定保留。其他分支专有节点通过 skip 排除，当前分支本身的业务节点不因合并丢失。
- 余额调整链路中内嵌的空原因拒绝步骤移出流程，该 API 用例仍保留。

## 验证

- 20 项本地整理校验通过，覆盖 70 个分支的请求/断言/认证/绑定顺序、前置准备、备份不变及事务回滚。
- 48 项现有流程、参数传递、持久化、报告回归测试通过；新增整理脚本 Ruff 检查通过。
- MySQL 写入后通过正式流程 Service 再次读取：9 个流程、70 个场景，全部停用且未执行。
- 第一次提交前遇到本机缺少 tzdata，整个事务已回滚；改用明确 UTC+8 时间戳后重新校验原快照并成功提交，无半成品或重复配置。

这些是配置校验结果，不是新业务场景运行通过。历史余额绝对值、日期、项目夹具和认证有效期需要重建或核对后才能启用。早会会触发全员结算，须使用隔离业务环境；本轮不执行共享环境扣款。
