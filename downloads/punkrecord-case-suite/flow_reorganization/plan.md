# PunkRecord 功能流程整理方案

仅整理测试平台配置，不执行业务接口。

功能流程按业务目标组织；场景是该链路的通过、拒绝、取消、重复操作等分支，不是单字段输入变体。
空文本、纯空格、长文本、数值格式、独立授权与文档检查只保留在原 API 正式用例下。

## 归并后的流程

| 流程 | 场景数 | 模板节点数 | 链路 |
|---|---:|---:|---|
|项目任务生成与同步|3|17|准备项目计划→生成/同步任务→修改计划→重复同步→核对任务身份|
|任务提交与验收|3|9|创建任务→提交完成→上级验收/退回→重新提交与验收|
|Bug创建与检索|1|10|创建不同标题Bug→关键词/分页检索→核对返回记录|
|获取贝利|34|21|创建任务→提交完成→主管验收→L0奖励审核→核对到账；含奖励计算、拒绝、重开冲销分支|
|贝利调整与防重|1|7|读取账户→调整余额→重复请求/异参重放→核对余额与流水|
|请假申请与审核|4|15|准备假期额度→提交请假→主管查看→批准/拒绝→核对假期余额|
|商城商品上架与下架|1|5|创建商品→发布→员工可见性→下架→员工不可见|
|商城下单与审核|21|24|准备商品与余额→购买商品→审核通过/拒绝/取消→核对订单、库存与冻结|
|扣除贝利（早会考勤）|2|10|录入早会信息→更新参会人→考勤结算→核对扣款及重复结算|

## 执行与历史

- 每个场景显式覆盖实际请求、认证节点、断言、提取及参数绑定；复用共享 API 节点，不把各参数变体再建成流程。
- 同场景节点必须按原顺序执行，只跳过其他分支专有节点。原参数传递与失败策略保留。
- 新场景不继承旧 latest_status/latest_run_id，不把历史通过冒充新场景通过。
- 旧流程与场景软删除；原 API 用例、接口、历史运行记录及快照均保留。
- 新模板保持停用。旧夹具/余额/日期不安全自动重放，准备新夹具并重新核对预期后才能启用。
- 早会结算会影响全体人员；必须在隔离业务环境准备早会文稿/录音与员工名单后执行，不能用手工扣款替代。
