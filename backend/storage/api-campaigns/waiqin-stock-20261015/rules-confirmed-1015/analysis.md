## 缺陷一：销售审批前没有锁库

- 场景 16313，批次 16417；失败节点 `sales_before_approval_stock`。
- 新销售订单 322（`SO20261015000018`），审批实例 1830，待审批状态 `2`，数量 3，商品 152。
- 创建前实际库存 10，锁定 0，可用 10。
- 预期创建后实际库存 10、锁定 3、可用 7；实际仍为 10、0、10。
- 订单详情的 `inventoryLocked` 为 `0`，只读数据库的 `locked_quantity` 也为 `0.00`，排除了仅库存接口展示错误的解释。
- 流程在审批前停止，未调用审批接口绕过失败前置，订单保留为待审证据。

定位方向：销售创建/提交进入审批的路径没有产生有效库存预占。需要在外勤小星业务服务检查该路径的锁库调用、事务与库存字段更新；本轮没有其业务实现代码，不能进一步确定内部根因。审批、拒绝、并发追加销售、关联销售退货和锁库商品转换等 13 条依赖场景暂缓。

## 缺陷二：拆箱数量不符合规格仍被接受

- 场景 16415，批次 16450；接口 `POST /business/warehouse/230/inventory/convert`。
- 源商品 200：件，规格 `1*24`；目标商品 201：瓶，规格 `1*1`；容量均为 `500ML`。
- 请求 `sourceQuantity=1`、`targetQuantity=25`，预期拒绝且两侧库存不变。
- 实际 `HTTP 200 / code 200`，返回“库存转化成功”。
- 数据库确认：源库存 `10 -> 9`，目标库存 `2 -> 27`，锁定量均为 0，错误换算确实落库。

定位方向：接口没有有效强制源数量、目标数量与装箱规格之间的守恒关系。业务服务应从商品规格推导目标量，或严格校验调用方传入值，并在一个事务内完成扣增；不能只依赖前端计算。以上为行为证据推断，不代表已经定位到某一行业务代码。

## 22 条拒绝码差异

超库存销售、无库存销售、非法退货参数、重复入库、禁止节点编辑/删除/提交、非法转换数量等请求都被业务拒绝，但返回 `HTTP 200 / code 500`，现有用例期望明确的参数/状态冲突类拒绝。

只读数据库逐条核验：22/22 的实际库存与锁定量均与失败请求前一致。它们当前属于接口错误码与用例约定不一致，不能据此认定为 22 个库存计算缺陷，也不能标记为通过。需统一接口约定；若确实保留业务码 500，应结合明确错误信息及库存不变断言调整个别预期，不能接受任意 500。
