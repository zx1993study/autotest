## 业务维度与规则

- 销售创建入口统一为 `POST /business/sales-order`。总仓、直营仓是出库仓库维度，不是两个创建接口。
- 数据库销售属性 `salesType` 为 `1=开发、2=复购`；仓库类型为 `1=总仓、2=直营仓`；客户类型为 `1=前端/终端、2=直营商、3=KOL`。本轮按仓库类型和客户类型交叉覆盖，不声称开发/复购两个属性、所有账号角色或所有客户记录均已覆盖。
- 销售审批前不锁库；审批通过且存在待确认订单时锁库，确认后扣实际库存并释放锁定；已自动完成的路径直接核对扣库结果，不重复确认。
- 从本次销售详情取得审批实例和关联单据。总仓销售为 `sales_order`；直营仓销售实测为 `sales_order_direct`，内置仓管审批 `flowId=0`，审批人是出库仓管理员。没有修改业务审批配置。
- 确认子单的状态 `2` 不能单独解释为已完成。终端/KOL自动完成单可返回状态2且已写确认时间；直营商待确认单也返回状态2但确认时间为空。模板结合销售主单状态、确认时间和库存决定分支；未知状态不视为成功。
- 退货仍按实际审批、待确认单依次处理；拆箱补件按装箱规格转换，提交即生效，无审批或确认。

旧批次16417基于“审批前应锁库”的错误预期，其业务缺陷结论撤销。原记录不删除、不回写为通过；同一场景16313已用新预期复测，最新批次16485通过。
